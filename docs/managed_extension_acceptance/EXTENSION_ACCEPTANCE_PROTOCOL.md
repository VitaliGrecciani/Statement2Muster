## 3. Результаты Цепочки 2: Отказоустойчивость, Persistence отзыва токенов и Идемпотентность миграций

Тестирование проведено на изолированном стенде с синтетическими базами данных (`scratch/run_extension_chain2.py`). Машинно-читаемый отчет сохранен в `chain2_fault_tolerance_results.json`.

### Сценарий 1: Живучесть отзыва токенов при рестарте и мульти-воркер топологии (C02 Hardening)
1. Выпущен реальный асимметричный RS256 JWT токен для пользователя `revocation_worker_test@statement2muster.com`.
2. Выполнен отзыв через эндпоинт `/api/v1/auth/logout`. Хэш токена сохранен в SQLite таблице `revoked_tokens`.
3. **Имитация холодного перезапуска / второго изолированного воркера:**
   - Произведена полная очистка in-memory кэша: `_revoked_tokens.clear()`.
   - Проверка `is_token_revoked(token)` на свежем воркере обратилась к SQLite и подтвердила статус отзыва (`True`).
4. Попытка вызвать защищенный эндпоинт конвертации `/api/v1/convert` с отозванным токеном была немедленно пресечена `EarlyAuthAndBudgetMiddleware` с кодом **HTTP 401 Unauthorized** (`detail: "Token has been revoked. Please re-authenticate."`).
5. **Вердикт:** **PASS**. Ошибка доступа или рестарт воркера не приводит к несанкционированному допуску.

### Сценарий 2: Идемпотентность миграций БД на копии легаси-схемы (B07 Hardening)
1. Сформирована база данных с устаревшей структурой (отсутствуют колонки `tenants.version`, `entitlements.payment_intent`, `usage_reservations.request_hash`).
2. В базу добавлены реальные тестовые записи: тенант `legacy_tax_firm@kanzlei.de`, активная подписка `pro`, закоммиченная квота (1 единица) и хэш отозванного токена.

   - Данные сохранены со 100% целостностью (`version=0`, `plan_code=pro`, `units=1`, хэш токена на месте).
4. Выполнен 2-й и 3-й прогоны `init_db()`:

## 4. Зафиксированные дефекты и внесенные исправления

В ходе выполнения сквозной приёмки были выявлены и устранены 2 точечных дефекта:

1. **Дефект UI-перехода при Logout в Chrome Extension (`extension/app.js`):**
   - *Симптом:* При клике на «Abmelden» и подтверждении диалога возникала ошибка `ReferenceError: applyLoggedOutState is not defined`, из-за чего кнопка не возвращалась визуально в состояние «Anmelden» до ручной перезагрузки вкладки.
   - *Исправление:* Заменен вызов несуществующей функции на штатную `initAuthState()`.
   - *Верификация:* Проверено в реальном браузере; UI моментально обновляется до «Anmelden». Релизные пакеты расширений пересобраны.

2. **Атомарность персистентности отзыва токена (`backend/app/api/endpoints/auth.py`):**
   - *Симптом:* В эндпоинте `/logout` сохранение записи в `revoked_tokens` выполнялось через `db.merge()`, но явный коммит сессии полагался на закрытие зависимости `get_db`.
   - *Исправление:* Добавлен явный `await db.commit()` непосредственно после добавления записи об отзыве токена.
   - *Верификация:* Проверено в Сценарии 1 Цепочки 2; гарантирована персистентность для мультиворкерных инстанций.
