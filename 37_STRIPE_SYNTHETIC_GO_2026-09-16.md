## 2. Закрытие Решения 36

Invoice.paid больше не отбрасывается по календарному last_event_created_at. Для финансовых событий используется last_invoice_event_created_at; сравнение оплаченных периодов выполняется относительно paid_through. В модели добавлено поле, в миграции предусмотрено добавление INTEGER DEFAULT 0 при его отсутствии.

Независимая локальная проба использовала одинаковые события I.created=201, S.created=202 и исходные timestamps=100:

| Проверка | Результат |
|---|---|
| S → I | current_period_start=2026-10-01, paid_through=2026-11-01 |
| I → S | Те же границы |
| Повтор оплаченного периода | current_period_start сохранён |
| Инвойс с окончанием раньше paid_through | Весь проверяемый объект остался неизменным |
| Invoice.paid для canceled entitlement | Весь проверяемый объект остался неизменным |

В раннере внешний event.created теперь задаётся явно. Сценарии 29–30 содержат проверки исчерпания квоты, отказа 429, восстановления 20 единиц, успешной конвертации до остатка 19 и сохранения 19 после повтора. Их удалённый результат в представленном отчёте — PASS.

Неблокирующая точность протокола: исполняемый раннер использует I.created=base+10 и S.created=base+20, тогда как текст результата называет 201/202. Требуемое отношение I.created<S.created сохранено; заменить текстовые константы фактическими значениями при следующем обновлении отчёта. Локальная независимая проба действительно использовала 201/202.
