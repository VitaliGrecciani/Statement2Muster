# Решение 25 — следующий рабочий блок: установленное расширение и Managed Auth

Дата: 2026-09-15. Основание: Решение 24 и указание PO отложить Stripe.

**В работу принимается Вариант 2: сквозная приёмка установленного расширения с Managed API.** Это следующий инженерный этап, не перепроектирование уже принятого C07. Stripe отложен по готовности PO, но его релизная приёмка не отменена.

## 1. Статус DATEV/BMD

Наличие каталога валидационного пакета и перечисленных разделов подтверждено локально. Содержимое экспортов, архив и заявленные 28 тестов в рамках этого решения независимо не перепроверялись. Статус B: пакет подготовлен по отчёту команды, практическая бухгалтерская приёмка ожидается. Подпись в пустом шаблоне и успешные unit-тесты не заменяют фактический импорт и сверку проводок.

Изменение StructuredCsvParser — новый код после принятой C07-сборки. Не переносить автоматически допуск старого image на новый код; фиксировать фактические commit/image/ZIP для новой приёмки и выполнять адресные регрессии изменённого парсинга. Повторное открытие всех инфраструктурных проверок не требуется.

## 2. Первая цепочка — штатный пользовательский путь

Начать с Chrome, затем проверить тот же выпускаемый Firefox-пакет, если Firefox входит в пилот. Устанавливать реальные ZIP/пакеты в чистые профили, а не проверять только JS-зондами.

Критерии:

1. Зафиксированы commit, SHA-256 пакета, версия браузера, API URL и image. Расширение действительно обращается к Managed API.
2. Пользователь через UI запрашивает OTP, получает письмо в согласованный тестовый ящик и входит. Не сохранять OTP/JWT в доказательном пакете.
3. Синтетическая выписка конвертируется через API; preview и скачанный файл соответствуют выбранному формату и исходным операциям. Отправка Bearer подтверждена без раскрытия его значения.
4. Ошибки 401/402/422/429 не включают молчаливую локальную конвертацию. Отсутствие сети/таймаут показываются понятным сообщением, интерфейс возвращается в работоспособное состояние. Ошибки сервера можно инъецировать в тестовой среде без боевых покупок.
5. Logout очищает клиентскую сессию; старый токен отклоняется сервером с 401. Перезапуск браузера не восстанавливает отозванную сессию. Повторный вход работает.
6. Очистка истории удаляет сохраняемые результаты/предпросмотр согласно принятому поведению, без ошибок UI.

Не добавлять новые механизмы авторизации без обнаруженного дефекта. Исправления — адресно по воспроизводимым сбоям.

## 3. Вторая цепочка — отказы и миграция

После штатного UI-пути проверить наличие уже принятых доказательств из Решения 16. Недостающие проверки выполнить на изолированном экземпляре с синтетическими данными:

- Отозванный токен остаётся недействительным после рестарта и на другой API-инстанции/worker при такой топологии. Ошибка доступа к состоянию revocation не должна превращаться в успешную авторизацию.
- Ошибка parser-worker не восстанавливает отозванную сессию; после восстановления доступ определяется актуальным состоянием авторизации.
- Миграция копии поддерживаемой предыдущей схемы сохраняет tenants, entitlements, quotas и revocations. Повторный запуск миграции безопасен; обычный вход/конвертация после неё работает.

Не отключать рабочую БД и не инъецировать аварии в продуктивный контейнер ради этой приёмки. Не переоткрывать уже закрытые C07 OOM/reclaim-сценарии.

## 4. Результат рабочего блока

Сохранить пакет `docs/managed_extension_acceptance/`: матрица сценариев, обезличенные результаты, артефактные хэши, фактические версии и список оставшихся дефектов. Различать пройдено, не выполнялось и заблокировано внешней зависимостью. Для закрытия Managed Extension требуются положительная установленная UI-цепочка и применимые отрицательные проверки; недостающие DB/revocation доказательства отмечать отдельно.

## 5. Параллельные задачи и общий допуск

PO организует DATEV/BMD-прогон у бухгалтера. Для организационного контура можно сейчас собрать фактическую карту данных/провайдеров и перечень документов для актуализации; юридическую приёмку назначить отдельно. Массовое переписывание юридических страниц не заменяет эту инженерную цепочку.

Общий Full GO остаётся невыданным. C07 закрыт для принятой сборки; успешная SMTP-доставка принята по свидетельству PO; Stripe отложен; DATEV/BMD ожидает практического подтверждения. Новых дефектов этим плановым решением не объявляется.
