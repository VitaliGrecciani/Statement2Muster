## 3. Уточнение объёма доказательств

Принятые ранее эксплуатационные результаты сохраняются как исторические доказательства с явной тестовой инструментализацией V6. Они не объявляются заново выполненными на V7.

V7 JSON содержит 4 Canary-строки × 3 области = 12 проверок, а не новый полный прогон 24/24. Ранее принятая матрица сохраняет свой статус. В V7 нет отдельной новой restart-цепочки; прежняя приёмка персистентности сохраняется при неизменной соответствующей реализации. Пустое поле healthz в JSON не считается новым измерением healthz.

V7 сохраняет число записей леджера, но не их отдельные статусы. Поэтому конкретное утверждение о RELEASED/COMMITTED именно в V7 не подтверждается этим JSON; соответствующая цепочка была принята по V6. Эти уточнения исправляют описание охвата и не являются новыми блокирующими условиями удаления filename-триггеров.
