# Решение 28 — Managed Extension, повторная приёмка

**Вердикт: дефект истечения revocation-кэша исправлен в проверенном локальном коде. Полный GO Managed Extension пока не выдан. Обнаружен открытый ключ провайдера в раннере; две заявленные интеграционные проверки остаются подменёнными.**

Дата: 2026-09-15. Прочитаны security.py, браузерный раннер, JSON-результаты; сопоставлен app.js из Chrome ZIP с рабочим исходником — байты совпадают. Удалённый прогон, письма, доступ к Resend и полный pytest не выполнялись.

## 1. Закрытие P1 из Решения 27

После удаления истёкшей RAM-записи код теперь продолжает чтение SQLite. Независимая изолированная проба неизменённой функции через AST дала:

- истёкший кэш + OperationalError → HTTPException 503;
- истёкший кэш + подтверждённая строка отзыва → True.

Ветка обхода из Решения 27 закрыта на уровне исходного кода. Приведение naive SQLite-даты к UTC присутствует. Серверное исполнение этого кода не было независимо воспроизведено.

## 2. Новый блокер: открытый Resend API key

В tests/acceptance/run_chain1_chrome.py:22 задан строковый литерал RESEND_API_KEY с полным значением ключа. Значение намеренно не воспроизводится в отчёте. Ключ используется для чтения сообщений, содержащих OTP. Его действительность и доступный набор разрешений не проверялись.

**Необходимое действие владельца ключа:** отозвать этот credential в Resend, создать замену с необходимыми минимальными правами, убрать литерал из исходников и передавать секрет через окружение/секрет-хранилище. Проверить историю Git и сохранённые логи/артефакты на этот секрет без вывода его значения. Удаление строки само по себе не отменяет уже раскрытый ключ. Подтвердить факт отзыва по идентификатору/времени, не публикуя новый ключ. Самостоятельно ключ не использовался и не отзывался.

## 3. Download и timeout: точный охват

**Download:** раннер заменяет chrome.downloads.download собственной функцией, читает Blob URL, сохраняет байты через Python и вызывает фиктивный callback с ID 1001. Это значимое улучшение: проверены байты, переданные кнопкой в download API. Но стандартный браузерный механизм загрузки/сохранения не был выполнен. Для закрытия этого критерия нужен один прогон с неподменённым downloads API, завершённым download item и проверкой фактически сохранённого файла. Данные сверки уже захваченного Blob можно сохранить как отдельное доказательство; это не бухгалтерская приёмка DATEV.

**Timeout:** тест ждёт 2.5 секунды и сам вызывает route.abort('timedout'). Он подтверждает реакцию UI на задержанную сетевую ошибку, но не доказывает, что приложение само завершает запрос, который не отвечает. Проверить реальный deadline клиента/согласованного ingress при зависшем ответе, без принудительного abort со стороны теста. Если клиентского deadline нет, реализовать ограничение и восстановление интерфейса; тест должен иметь отдельный аварийный предел времени, не засчитываемый как успешный таймаут приложения.

## 4. OTP и происхождение сборки

Чтение содержимого отправленного письма через Resend устраняет обход через SQLite, но само по себе не доказывает получение письма конечным ящиком. Ранее подтверждённая PO доставка остаётся принятой; новый автоматический тест следует описывать как чтение письма у провайдера и не приравнивать его без дополнительных данных к mailbox delivery.

JSON chain1 указывает commit c38eaed34fe5c4cde904397dad7840444b18d439, доклад — 76f66a33ffd38e2dae84bc108d301ef5f2778f9b. Новый image ID указан, что исправляет прежнее повторное использование ссылки на старую сборку, но необходимо объяснить соответствие тестируемого кода и commit: сохранить build revision/хэши актуальных модулей из контейнера. Image ID и RepoDigest не следует автоматически считать одной сущностью только на основании совпадающей строки: приложить фактические inspect-поля. Новый контейнер и health version сами по себе не доказывают состав исходников.
