Блокировка shared RAM budget рассматривается как атомарность admission, а не обещание хранения до самого конца TTL при любом LRU-давлении. Ранее принятый контракт 410 при вытеснении/перезапуске сохраняется. Текущая SQLite-транзакционная модель также важна для конкурентного поведения: проба с искусственной остановкой перед commit не подтвердила вытеснение другим конвертационным запросом, поскольку второй writer блокировался SQLite. Это не основание объявлять обнаруженным новый дефект или утверждать эквивалентность поведения иной СУБД.

## 3. Browser и build evidence

Расширенный smoke прошёл для Landing и обоих каталогов расширений. Добавлен BMD NTCS 8-column, сохраняются проверки DATEV/BMD Bankauszug, ошибок/Valuta, reset/race и восстановления интерфейса. Проверка платформенных Firefox overrides теперь находится в самом `--check`, а не только в отдельной аудиторской сверке.

Дополнительно независимо проверено зависшее чтение HTTP-тела через loopback TCP-сервер:

- Реальная `switchPreviewFormat` расширения получила успешные headers, затем прекратила чтение тела примерно за **259 мс** при deadline 250 мс. Результат false, контроллер очищен, download disabled, показана ошибка таймаута.
- Реальная `fetchLandingExportBytes` получила headers и завершилась примерно за **263 мс** при deadline 250 мс. Контроллер очищен, download disabled, currentDemoBytes=null.

Эти пробы ожидают завершения самой функции и фиксируют получение headers; они не опираются только на наличие старого сообщения об ошибке в DOM. Рекомендуется сохранить такую синхронизацию и в основном smoke: последовательные проверки одинакового текста предупреждения сами по себе слабее проверки завершения конкретного запроса. Это замечание к устойчивости доказательства, не блокер реализации, поведение которой отдельно подтверждено.

Границы приёмки: обе папки расширений исполнялись в **Chromium с подменой extension API**. Это не установка пакета в нативный Firefox. ASGI bridge не является публичным reverse proxy. Эти границы явно сохраняются в релизном протоколе.

## 4. Условия выпуска

### До развёртывания

1. Получить ранее предусмотренное подтверждение Product Owner на deploy. Данное решение — архитектурный допуск, а не выполнение deploy от имени PO.
2. Зафиксировать принятые изменения отдельным release commit. Сопоставить его дерево с `source_manifest.json`, сохранить SHA-256 пакетов Chrome/Firefox и digest образа. Не включать непроверенные изменения автоматически из всего dirty tree. При содержательных изменениях после аудита повторить соответствующие проверки; если commit только фиксирует те же байты, новый полный прогон лишь ради нового SHA не требуется.
3. Зафиксировать принятое PO значение default Valuta, сохранив явное раскрытие замены booking date и текущий запрет платного экспорта без требуемого opt-in.

### После контролируемого развёртывания, до публичного допуска

| Gate | Обязательное подтверждение |
| --- | --- |
| Сборка/runtime | Release commit → image digest → container ID → исходники работающего контейнера; health, миграции/БД, RAM TTL 600s, общий бюджет, лимиты файлов, политика JWT. Санитизированный inspect без секретов. |
| Reverse proxy | Через публичный HTTPS: Cache-Control `no-store, private` на финансовых CSV/JSON и относящихся к ним ошибках; отсутствие proxy caching; корректные Content-Type, Content-Disposition и CORS/exposed headers. Проверить 401/403/410/413/422, включая ограничения самого proxy. |
| Экспорт и квота | Один оплаченный canonical разбор; переключение DATEV, BMD Bankauszug и BMD NTCS без повторного списания. При blocked parser/Valuta/export — preview с 422 и нулевой COMMITTED delta. Сверить фактические скачанные BOM/Windows-1252, CRLF, колонки, знаки, суммы, Konto/Gegenkonto и reference. |
| Изоляция/replay | Другой tenant не получает результат, просроченный JWT отклоняется. Replay побайтово совпадает, не вызывает parser и не продлевает TTL. TTL/restart/eviction дают 410 без повторного списания. Проверки admission boundary выполнять на изолированной конфигурации, не уменьшением RAM-бюджета рабочего сервиса с клиентскими запросами. |
| UI и пакеты | Установленные Chrome/Firefox: реальное скачивание, доступ к HTTPS, смена форматов, Valuta, reset/новая загрузка во время ответа; header/body timeout и восстановление на convert/export. |
| Ограниченность обработки | Несвязный максимальный синтетический batch обрабатывается с блокирующей диагностикой; health остаётся отзывчивым. Не выдавать BALANCED при исчерпанном бюджете поиска. |
| Внешняя BMD-приёмка | Реальный импорт 22-колоночного файла в согласованный профиль BMD NTCS Bankauszugsverbuchung: даты, знаки, назначение/контрагент, число строк, суммы и баланс. Зафиксировать версию программы, настройки профиля и sign-off бухгалтера. |

У каждого gate в релизном протоколе должны быть конкретные сборка, результат, доказательство и исполнитель. Неуспех gate блокирует публичный выпуск затронутого пути; исправление нельзя объявлять принятым только по прежним локальным PASS.

Ключи API остаются согласованными: `bmd_bankauszug` — новый 22-колоночный профиль; `bmd` — прежний восьмиколоночный; `bmd_ntcs` — его алиас; `datev` и `muster_csv` сохраняют совместимость. Успешный CSV-тест не означает универсальную сертификацию любых импортных масок BMD/DATEV.
