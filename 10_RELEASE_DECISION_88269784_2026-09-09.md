## 3. Точная интерпретация свидетельств

- Новый OTP-зонд получает код из синтетического memory inbox, а не БД. Это проверяет API flow, но не реальную доставку SMTP.
- UI-зонд исполняет извлечённую настоящую processBackendConversion с раздельными stub local/session stores. Это доказательство отсутствующего заголовка, не полноценный браузерный end-to-end тест.
- C03 касается сохранения email/OTP; он не доказывает запись банковских файлов этим сервисом. OTP дополнительно остаются в неограниченном _test_inbox и логируются адреса получателей.
- C06 не означает выдачу просроченного кэша: get корректно возвращает miss. Нарушена заявленная гарантия освобождения RAM по сроку. Сам RAM cache не доказывает durable запись финансового результата.
- Старый probe_round4 проверяет конкретный default outbox path. В новом изолированном прогоне он показывает outbox_on_disk=false, поскольку EMAIL_OUTBOX_PATH переопределён. Собственный зонд проверяет фактический configured path и подтверждает запись. Поэтому один boolean без контекста не доказывает Zero Retention.
- C05 не доказывает обход платного доступа пользователем с null-plan: effective fallback остаётся Trial. Доказаны нарушение состояния и незавершённый authoritative fulfillment.
- Совпадение архивов подтверждает упаковку текущего кода, включая выявленные дефекты; не подтверждает работоспособность сценария.

Antigravity: сначала исправить C01–C05 и добавить assertions по ожидаемым инвариантам. Затем C06–C07 и выполнить image/idle/crash/multiworker проверки. После этого подготовить ограниченный подтверждённый corpus, actual import evidence и согласованную privacy/AVV документацию (C08). Пересобрать ZIP, зафиксировать новый HEAD/хеши и повторить тесты на этих артефактах.

Не требуется заново доказывать исправленные отдельные примеры как новые требования. Требуется закрыть конкретные остатки первоначальных пяти условий. Запуск Python script с exit code 0 и 25 зелёных tests не заменяет проверку приведённых инвариантов.
